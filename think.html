QTE 手感三问：框太小、会卡、手指挡住眼睛

三个问题里前两个是工程，已经改了。第三个是设计，根子在一句话：我们把「眼睛要看的」和「手指要按的」放在了同一个地方。眼睛去了框，画面就没人看；手指去了圈，圈就被盖住。解法不是把框做大，而是把两件事分开：提示留在画面里，手只负责左右。

一、三个问题各自的根因

1 · 框太小、怕误操作框只占下 60%、宽 22%；而且圈画在框里，视觉上暗示「要点到圈上」，其实引擎一直是按那一侧任何地方都算。已改：框从上到下、宽 24%；开始页写明「按哪都行」
2 · 会卡一下三个来源：① github.io 在国内的网络缓冲；② 教学档故意停下等你、二三档临近判定点放慢，不知情会当成卡；③ 按下的瞬间视频从慢速回到 1 倍，iOS 要重新对一次音画。已改：整段 14MB 先下载到内存再播，网络不再参与；慢动作、特效都能关；成绩里带缓冲次数和丢帧数，一看就知道是哪种卡
3 · 手指挡住、眼睛离开画面提示在框里＝眼睛必须去框；圈是目标＝手指必须盖住它。这不是参数问题，是布局把注意力绑错了地方。本稿主题 · 下面五个方向

D · 词汇减肥：第一次玩只认三种

第一次玩的人要同时读「跟节奏点」「滑住」「满了就松」这些字，读字就是眼睛离开画面。手势从 7 种减到 3 种，标签只在教学卡出现一次，玩的时候只有图标。

四、放在一起看

方向解决哪个问题改动量风险先例
A 提示进画面眼睛离开画面 / 手指遮挡中：每个点要标画面坐标（32 个）画面里的圈会压住表演；贴错对象会误导Heavy Rain、底特律
B 边缘光带眼睛离开画面小：只改两侧框的样式与动画只靠亮度分不清手势类型，要配 A 或 CPS5 灯条、Ambilight
C 声音先行注意力分散 / 节奏段小：加两声预拍 + 震动有人关声音玩；预拍太多会吵Rhythm Heaven、太鼓
D 词汇减肥第一次玩看不过来小：改数据，不改引擎后半段的变化少了，要靠节奏补几乎所有手游 QTE 只有点/按/滑
E 手指在下提示在上手指遮挡 / 框太小已做：框全高；提示位置待上移提示离边远了，余光稍弱iOS 键盘气泡

五、建议的顺序

  1. 今晚就能试：A 的简化版 + E。demo 开始页多了「提示位置：画面里 / 两侧框里」，默认画面里。同一段打两遍，感受眼睛是不是留在画面上了。
  2. 下一版：B + C。两侧框改成会呼吸的光带，每个动作前加两声预拍和一次震动。这两样都是小改。
  3. 再下一版：A 的完整版。把 32 个点逐个标到画面里的对象上（机甲的手、来袭的碎片），让提示真的「长在表演上」。
  4. D 看情况。如果试玩的人反馈「看不过来」多于「太单调」，就减词汇。

六、怎么验证，不靠感觉

给每个试玩的人两个问题，加上结束页「复制成绩」里的数据：

  1. 「你打的时候，眼睛看的是画面还是两边的框？」——这是第三个问题的唯一指标。
  2. 「有没有哪一下你没看提示也按对了？」——答得出来，说明声音和节奏起作用了。
  3. 成绩文本最后一行：缓冲 N 次 / 丢帧 a/b / 源：本地整段或网络。缓冲为 0 还卡，就是渲染；缓冲不为 0，就是网络。

我的看法

我最想先试的只有一件事：把 Q05「挡」那一下的圈，从右框里挪到画面中机甲抬起的那只手上，其他什么都不改。如果你打那一下的时候眼睛没有离开机甲，这条路就对了；如果还是忍不住去看框，说明问题不在提示的位置，而在「框」这个东西本身太像按钮——那就该把框去掉，只留两条会亮的边。我倾向于后者会赢，因为框是我们画给自己看的规则，玩家只需要知道左和右。
